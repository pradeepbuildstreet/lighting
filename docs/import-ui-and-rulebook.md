# Import lifecycle UI and catalogue rulebook

The v3 UI now hashes referenced images, persists an owner-scoped request/input receipt before preview writes, prepares a server job, stages missing images sequentially, permits explicit re-staging, confirms updates and commits the exact job. Recover by stored job ID or original request key. Changed input cannot reuse a pending request receipt. After refresh reselect the image folder for unstaged files. Unknown outcomes block replacement batches; recover first. HTTP rate limits stop staging; resume after recovery/wait rather than creating another job.

Session storage and secure-context Web Crypto are required before preparing a preview. Receipts store identifiers/digests, not image bytes or preview tokens. Server ownership checks still apply. A different signed-in owner clears only the old local link, not any server job. If an identical-input request was deduplicated to another canonical job and its response was lost, recovery by the new key may report not recorded: reselect and retry the exact original preview input under the same key. Durable alias mapping is not implemented.

Reference Data now exposes one-record-at-a-time editing for group single/multi policy and default/per-kind JSON naming rules with optimistic revisions and auditing. Existing form name-suggestion HTTP requests are intercepted before the old router and use the persisted kind override/default, falling back to version-1 code when migration 09 is absent. Applying a rule does not rename existing products or overwrite manual names. Group rules remain optional for drafts.

Migration 09 defaults all groups to multi and adds a derived single-group slot plus unique index on product_tags. Triggers derive the slot from the actual tag's group, reject moving tags between groups and rebuild slots when policy changes. A group cannot switch to single while a product has multiple selections: the API prechecks, and the unique index rejects conflicting slot rebuilds. Existing product_tags UPDATE invalidation triggers may run during policy changes; test their review/publication effects before applying. Database trigger, locking, privilege and concurrent-write tests have not run.

Eight import-helper cases and four rule-validation cases passed locally. HTTP lifecycle tests, same-job retries, browser reload/receipt recovery, mode/owner changes, staged-file loss, database migrations and constraints, settings optimistic-lock tests, TSX type-check, full suites and production build remain unverified. No migrations or environment flags are applied. Existing signature inspection is still basic framing, not full image decoding or malware scanning.

General-editor SKU read-only presentation, richer tag-selection UX, scoped master export beyond 1000 products, automatic cleanup/monitoring, durable request aliases and production rollout verification remain pending. Assigned SKU immutability is enforced by the service and staged DB guard, but the legacy general-editor field is still rendered editable and rejected on changed saves. Do not describe this commit as full production activation.
