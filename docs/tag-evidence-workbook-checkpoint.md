# Tag-aware evidence and Excel v2 parser checkpoint

Staged modules only; this commit does not mount APIs, generate downloadable templates, create import jobs, run duplicate audits, change review/publication state or activate the tag-product cutover.

The scorer uses tags-evidence-v2, matching the storage guard. Same-kind candidates use brand/model, name overlap, sparse minimal attributes and capped group-qualified tag overlap. Missing classification earns no positive match. Exact byte hashes or brand/model can flag cross-kind candidates for human misclassification review. Scores are provisional heuristics, not probabilities or calibrated accuracy claims. loadEvidence batches attributes, tags and image hashes in three queries for at most 1000 supplied products; it does not scan the candidate corpus. The future audit service must lock and enumerate a complete corpus or require a complete background scan rather than silently truncate it, retain revision/algorithm/corpus safeguards, and never auto-approve.

Workbook v2 requires Metadata format_version=2 and Products; ProductTags is optional and uses SKU/group-code/tag-code rows. Reference sheets are lookup aids, not instructions to create vocabulary. Header/row limits, plain-cell checks and explicit update tag modes apply. Existing inspectZip is reused by readWorkbook. Reference maps avoid per-row vocabulary scans. Resolve only referenced code sets and group-qualified pairs, plus category ancestors/configuration; categories must include computed ancestry_active. Row business errors retain worksheet/row context. Do not discard ProductTags error rows when deciding commit readiness.

The preview/commit service must capture reference_fingerprint, re-resolve the same relevant reference set at commit, reject changed fingerprints and product revisions, require explicit common-field/category replacement confirmation, and use the shared writer for a single atomic import transaction. Job-format versioning, preview tokens/replay, template generation, routing and UI remain pending.

Validation: 36 isolated scorer/row/worksheet-contract tests passed; one real-XLSX roundtrip test was skipped because ExcelJS is absent in the isolated environment. No PostgreSQL hydration query execution, HTTP/auth/import/review integration, real concurrency, frontend build, accuracy calibration or live performance verification is claimed. The real-XLSX test will run where the existing backend dependencies are installed. No changes to current customer/wishlist/image-loading paths.
